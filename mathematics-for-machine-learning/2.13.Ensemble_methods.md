## 13.1 Decision Trees (CART)

A decision tree recursively partitions feature space with axis-aligned splits, predicting a constant
(majority class, or mean for regression) in each leaf.

**Split selection.** At each node, pick the feature/threshold $(\boldsymbol{j}, t)$ that maximizes the
reduction in impurity:
$$\Delta = I(\text{parent}) - \left(\frac{n_L}{n} I(\text{left}) + \frac{n_R}{n} I(\text{right})\right)$$

Impurity measures for classification:
- **Gini impurity**: $I = 1 - \sum_k p_k^2$ — expected error rate if you label a random point using the
  class distribution at that node.
- **Entropy**: $I = -\sum_k p_k \log_2 p_k$ — used for **information gain** ($\Delta$ above with entropy).
- **Regression**: impurity is variance / MSE reduction instead.

> **Intuition.** Gini and entropy are both concave functions of the class distribution, maximized at
> uniform ($p_k = 1/K$) and zero at a pure node ($p_k \in \{0,1\}$) — greedily picking the split that
> most reduces this is a local, myopic proxy for "make the resulting subsets as pure as possible."
> Gini and entropy almost always pick the same splits in practice; Gini is cheaper (no log) and is
> sklearn's default.

> **Usage.** A single decision tree is a **high-variance, low-bias** model: grown to full depth it can
> perfectly fit (memorize) training data, but small changes in the training set produce very different
> trees. This variance is exactly what bagging (§13.2) and random forests (§13.3) exploit.

> **Practicality.** Trees are scale-invariant (splits are threshold comparisons, so monotone
> transformations of a feature don't change the tree) — no feature normalization needed, unlike
> linear/SVM models. Overfitting is controlled via `max_depth`, `min_samples_leaf`, `min_samples_split`,
> or post-hoc **cost-complexity pruning** (minimize $\sum_{\text{leaves}} I(\text{leaf}) + \alpha \cdot
> |\text{leaves}|$, i.e., an explicit complexity penalty analogous to L1/L2 regularization elsewhere in
> this book).

## 13.2 Bagging (Bootstrap Aggregating)

Train $B$ base models independently, each on an i.i.d. **bootstrap sample** (sample $n$ points with
replacement from the $n$-point training set), then average (regression) or majority-vote
(classification) their predictions:
$$\hat{f}_{\text{bag}}(\boldsymbol{x}) = \frac{1}{B}\sum_{b=1}^B \hat{f}_b(\boldsymbol{x})$$

**Variance reduction.** If each $\hat{f}_b$ has variance $\sigma^2$ and pairwise correlation $\rho$:
$$\text{Var}(\hat{f}_{\text{bag}}) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$$

> **Intuition.** This is the same bias-variance decomposition used throughout ML: averaging $B$
> identically-distributed but imperfectly-correlated estimators shrinks the variance term toward
> $\rho\sigma^2$ as $B \to \infty$ (the uncorrelated part averages away, the correlated part doesn't).
> Bagging does **not** reduce bias — averaging many similarly-biased trees still has the same bias as
> one tree — which is exactly why bagging is paired with **high-variance, low-bias** base learners
> (deep, unpruned decision trees), not with already-low-variance ones (e.g., linear regression).

> **Usage.** Because each bootstrap sample leaves out ~36.8% of points ($\lim_{n\to\infty}(1-1/n)^n =
> e^{-1}$), those **out-of-bag (OOB)** points give a free, unbiased validation estimate without a
> separate held-out set — one of bagging's practical advantages.

> **Practicality.** Bagging trains $B$ independent models — trivially parallelizable (unlike boosting,
> §13.4, which is inherently sequential). This is a common interview trade-off question: "why is random
> forest training embarrassingly parallel but XGBoost isn't?"

## 13.3 Random Forests

Random forests = bagging + one extra randomization: at each split, only consider a random subset of
$m \approx \sqrt{D}$ (classification) or $D/3$ (regression) features, rather than all $D$.

> **Intuition.** Plain bagged trees are still highly correlated with each other: if one feature is very
> strong, nearly every bootstrapped tree will split on it near the root, so the trees end up similar
> ($\rho$ stays high in the variance formula above). Restricting each split to a random feature subset
> decorrelates the trees — forcing some trees to discover the second- and third-best signals — which
> lowers $\rho$ and hence lowers $\text{Var}(\hat{f}_{\text{bag}})$ further than bagging alone.

> **Usage.** Feature importance from a random forest (mean impurity decrease per feature, or
> permutation importance) is a fast, model-agnostic-ish way to rank feature relevance — frequently asked
> as a follow-up ("how would you get feature importance out of a random forest, and what's a pitfall of
> the naive version?" — impurity-based importance is biased toward high-cardinality / continuous
> features; permutation importance on a held-out set is the fix).

> **Practicality.** Random forests are a strong, low-effort baseline for tabular data: robust to
> irrelevant features and outliers, no feature scaling needed, minimal tuning (mainly `n_estimators`,
> `max_depth`, `max_features`) compared to gradient boosting's larger hyperparameter surface.

## 13.4 Boosting: AdaBoost and Gradient Boosting

Unlike bagging (parallel, variance reduction), boosting builds models **sequentially**, each one
correcting the errors of the ensemble so far — primarily a **bias reduction** technique.

### AdaBoost

Maintain per-sample weights $w_n$, initialized uniform. At each round $m$:
1. Fit a weak learner (often a depth-1 "decision stump") on the weighted data.
2. Compute weighted error rate $\epsilon_m$, set learner weight $\alpha_m = \frac{1}{2}\ln\frac{1-\epsilon_m}{\epsilon_m}$.
3. Up-weight misclassified points: $w_n \leftarrow w_n \exp(\alpha_m \cdot \mathbb{1}[y_n \neq \hat{y}_n])$, renormalize.

Final prediction: $\text{sign}\left(\sum_m \alpha_m \hat{f}_m(\boldsymbol{x})\right)$.

> **Intuition.** $\alpha_m$ is large when $\epsilon_m$ is small — accurate weak learners get more say.
> Re-weighting forces the *next* weak learner to focus on the points the ensemble currently gets wrong,
> so each new learner targets the current ensemble's residual mistakes rather than re-learning what's
> already known.

### Gradient Boosting

Generalizes AdaBoost: fit each new tree to the **negative gradient of the loss** w.r.t. the current
ensemble's predictions (functional gradient descent in prediction-space), scaled by a learning rate
(shrinkage) $\eta$:
$$F_m(\boldsymbol{x}) = F_{m-1}(\boldsymbol{x}) + \eta \cdot h_m(\boldsymbol{x}), \quad h_m \approx -\nabla_{F} \, \ell(y, F_{m-1}(\boldsymbol{x}))$$

For squared-error loss, the negative gradient is just the residual $y - F_{m-1}(\boldsymbol{x})$ — "each
tree fits the previous ensemble's residuals" is the standard intuition, but it generalizes to any
differentiable loss (log-loss for classification, quantile loss, etc.) via the gradient, not literal
residuals.

**XGBoost** adds: a **second-order (Newton) Taylor expansion** of the loss (uses both gradient $g_i$ and
Hessian $h_i$ per sample, giving a closed-form optimal leaf weight
$w_j^* = -\frac{\sum_{i \in j} g_i}{\sum_{i \in j} h_i + \lambda}$), explicit **L1/L2 regularization on
leaf weights**, a regularization term penalizing the number of leaves, and engineering optimizations
(column block storage, approximate quantile split-finding, sparsity-aware default direction for missing
values).

> **Intuition.** The bias/variance story flips relative to bagging: a single weak learner (shallow tree,
> even a stump) has high bias, low variance. Boosting sequentially reduces **bias** by chasing residual
> error; each additional tree can, in principle, keep reducing training error toward zero — so boosting
> is much more prone to **overfitting** than random forests if left unchecked, which is exactly what
> shrinkage ($\eta$), tree depth limits, subsampling (stochastic gradient boosting), and XGBoost's
> explicit regularization terms are designed to control.

> **Usage.** Common interview framing: *"When would you pick a random forest over XGBoost, or vice
> versa?"* — Random forest: fewer hyperparameters, trains in parallel, more robust to noisy labels and
> outliers (each tree still sees the raw labels, not residuals), good default when you need something
> fast and hard-to-misconfigure. Gradient boosting/XGBoost: usually higher accuracy on structured/tabular
> data given careful tuning (learning rate, depth, `n_estimators`, regularization), but sequential
> (slower to train), more sensitive to noisy labels/outliers (later trees keep fitting their residuals),
> and easier to overfit without early stopping on a validation set.

> **Practicality.** Both are largely superseded by deep learning on unstructured data (image/text/audio)
> but remain SOTA-competitive and far cheaper to train/serve on tabular data — this "when NOT to use deep
> learning" framing is itself a common system-design/ML-breadth interview question (see also the
> practicality note in [Support Vector Machines](2.12.Support_vector_machines.md)).

## 13.5 Bagging vs. Boosting — Summary Table

| | Bagging (Random Forest) | Boosting (AdaBoost / GBM / XGBoost) |
|---|---|---|
| Base learner | High-variance, low-bias (deep trees) | High-bias, low-variance (shallow trees/stumps) |
| Trains | In parallel, independently | Sequentially, each depends on the last |
| Primarily reduces | Variance | Bias |
| Overfitting risk | Low (more trees rarely hurts) | Higher (more rounds can overfit; needs shrinkage/early stopping) |
| Sensitivity to outliers/noisy labels | Lower | Higher (later learners chase residuals of mislabeled points) |
| Typical tuning burden | Low | Higher (learning rate, depth, regularization, rounds) |

## Quick Interview Q&A

**Q: Why does bagging reduce variance but not bias, while boosting reduces bias?**
Bagging averages i.i.d.-ish estimators of the *same* target function — averaging cancels variance around
a shared expected prediction (the bias of that expected prediction is unchanged). Boosting builds an
additive sequence of models where each new term explicitly targets the *current residual/gradient* of
the loss — driving down the ensemble's bias term by construction; variance is a secondary concern
controlled via shrinkage/regularization, not the primary mechanism.

**Q: Why is random forest embarrassingly parallel but XGBoost is not?**
Each random forest tree only depends on its own independent bootstrap sample and random feature subset —
zero inter-tree dependency. Each boosting round's tree is fit on the *residual/gradient of the ensemble
built so far*, so tree $m$ cannot be built before trees $1, \dots, m-1$ exist.

**Q: Feature scaling — do tree ensembles need it?**
No. Splits are threshold comparisons on individual features; any monotone transform of a feature
(log, standardization, min-max) produces the identical tree. This is unlike linear models, SVMs (§12),
or gradient-based deep learning, where scale directly affects the optimization landscape/regularization.
